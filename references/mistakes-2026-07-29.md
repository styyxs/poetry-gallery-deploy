## 3 层根因（v2 已修复）

### 根因 1：技能依赖图错过（设计层面）

我接手时，skill 库里有 2 个相关 skill：

```
kids-illustration-html            （管 HTML 内嵌插画）
ancient-poem-kids-picturebook    （管 GitHub Pages 主页卡片 + 部署）
```

我**只读了第一个**（因为诗任务是 kids-illustration-html 的主要场景），**没读第二个**（因为我以为 GitHub Pages 部署是次要场景）。

**修复（v2）**：合并为单 skill `poetry-gallery-deploy`，消除"该读哪个"的歧义。

### 根因 2：字段契约没强制（脚本层面）

`poems.json` 的字段定义（v1 实际状态）：

| 字段 | 是否必填 | 后果 |
|---|---|---|
| title | 必填 | 缺则 JS 报错 |
| author | 必填 | 缺则显示空 |
| file | 必填 | 缺则卡片 href 错误 |
| summary | 必填 | 缺则卡片摘要空 |
| tags | 必填 | 缺则 fallback SVG |
| **illus** | **可选** | **缺则 fallback SVG** ← 这是问题 |

前端 JS 有 `p.illus ? <img> : pickIllus(tags) → SVG` 的 fallback 逻辑。**fallback 让 illus 字段"可选"，导致我没生成 card_cover 也能上线。**

**修复（v2）**：`validate.py` 强制每条 poem 记录必有 `illus` 字段，否则返回非零退出码。**frontend 的 fallback 逻辑仅作为"系统挂了"的兜底，不允许触发**。

### 根因 3：existing data drift（运维层面）

之前 Work Buddy 时代 3 首诗本来有 illus 字段。后来某次清理 poems.json（可能是为了去 stale 字段），illus 一起被清掉了。**之后没自动补回**——这是一个隐性数据漂移。

**修复（v2）**：
- `validate.py` 默认对历史数据也跑——只要 poems.json 任何一条记录没 illus，就报错
- README 写明"运行 validate.py 是日常运维的一部分，不是只在加新诗时跑"

## 不要再犯的 3 个铁律

1. **触发 GitHub Pages 部署任务时，必须先读 references/mistakes-2026-07-29.md**
2. **任何对 poems.json 的修改（包括手工编辑），修改后必跑 validate.py**
3. **绝不允许 poetry-gallery-deploy skill 在 poems.json 没有 illus 字段的情况下继续**

## 教训对 skill 设计的影响

- **冗余覆盖**：把"该读哪几个 skill"的判断，编码到 deploy.py 内部（agent 调用 deploy.py 即可，不需要手动选择 skill）
- **卡门设计**：validate.py 是必经关卡，不可绕过
- **显式 contract**：README 把"每首诗必须有 illus 字段"写成不可商量的规则
